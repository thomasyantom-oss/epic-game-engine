# Feature #3 伤害类型 / 抗性 — Running Notes(脑暴 WIP,不是 spec)

> 这是脑暴过程中的备忘,**不是定稿 spec**。等"减伤公式"和"精神伤害色"两块也聊定,再正式落 design doc + writing-plans。
> 维护:Claude (Senior SDE)。最后更新 2026-06-01。

## 设计哲学锚点(贯穿全程)
- **纵向的不完美 > 横向配平**:游戏的性格来自"敢于专注、敢于不要",不是把各家优点缝成缝合怪。缺点=主动砍掉的;亮点=因为砍了,剩下那条线才够纯够深。
- **大道三千,每条道固定且要专注才成道**:人物多方向发展,但路是固定的,不鼓励东摘西摘拼缝合 build。
- **build = 职业 + 专精 + 装备 + 未来机制**(确认 B 不是 A):伤害类型只是 build 的一块原料,不是"道"本身。
- 优雅的判准(用户举 PoE 红绿蓝=力敏智为范例):**小而正交的基底 + 全局复用 → 组合爆炸但不泛滥**。

## 已锁定(基调)
1. **伤害类型 3 种,固定,引擎级基底:物理 / 法术 / 精神。** 灵感来自"五主属性 → 三强度通道"的非对称收敛(力/敏/体→物理强度,智→法术强度,意→精神强度),不是 5=5 的暗黑式映射。
2. **三条常规抗性:物抗 / 法抗 / 精抗。** 这是"常规减伤"层,人人有、装备常 roll。零泛滥(永远只有 3 条)。
3. **元素 = 第二条正交轴,独立乘区**,与伤害类型完全解耦。每技能 **0 或 1 个**元素。例:火球=法术·火,背刺=物理·无。
4. **元素加成%**:独立乘区,既加伤害又驱动额外效果(50% 火 → 多伤害 + 额外灼烧回合)。**rider 效果以后做**,现在只把 `元素加成%` 当数值带着。
5. **元素抗性 = 稀有"最高贵"属性**:不进常规装备词缀池,只由特殊技能 / 怪物种类赋予。默认所有人元素抗 = 0/无 → 永不泛滥。
6. **元素可扩展 = 纯数据**:3 种伤害类型写死在减伤收口里;元素处理是泛型的(读 `skill.element`、攻方 `元素加成[element]`、守方 `元素抗[element]`,取不到默认 0/无)。加一个"雷"= 加数据(名字+颜色,以后配 rider),**减伤代码一行不动**。
7. **红线(继承 F2 §1)**:抗性是高级属性,基础属性/等级**不白给**,只来自装备/buff/专精。`derived_stats.js` 不写抗性。

## 减伤模型(已定:按"投放方式"分流)

减伤**不按伤害类型分流,按"普攻 vs 技能"分流**——这是为了让**站位**有意义(纯堆三抗谁站哪都一样 → 站位失去意义)。

- **普攻(basic)**:**只被护甲减免**;护甲走**曲线** `减伤% = 护甲/(护甲+K)`(天然递减、自带软上限、不用硬 cap;K 随等级/区域调,**一个旋钮**)。护甲只挡普攻——给"前排高甲坦克吃普攻"的定位。普攻射程默认只够最前(站位系统细化见 future note)。
- **技能(skill)**:被**对应类型抗% 减免**(物抗/法抗/精抗),`×(1−类型抗%)`,cap 75 / 负抗=易伤。技能可选后排。
- **元素**:独立乘区,攻方 `×(1+元素加成%)`,守方 `×(1−元素抗%)`(稀有,默认 0);无元素 → ×1。
- **防御姿态等** ×defendMult 照旧。

骨架:
```
final_技能 = ⌈ raw × (1+元素加成%) × (1−类型抗%) × (1−元素抗%) × defendMult ⌉
final_普攻 = ⌈ raw × (1 − 护甲/(护甲+K)) × defendMult ⌉      // 护甲专挡普攻;普攻一般无元素
```
注:**护甲 与 物抗 是两条独立防御**——护甲挡普攻,物抗挡"物理技能(顺劈/背刺)"。故意分开,分开才有站位玩法。物理技能走物抗(三抗之一),不走护甲。

**数值待定(以后细调,不影响结构):** 护甲曲线 K(随等级)、抗性 cap(提案 75)、易伤 floor、元素加成% 与各元素 rider。落地用 F2 的"占位归一化先保战斗不崩,再配抗性做手感"。

## 精神(已定)
精神 = **第三条正常技能伤害色**,吃精抗,和物/法完全对称。**控制/免控不属于减伤地基**(控制由技能定义,正交)。`豁免`(免控判定)**搁置**:太 heavy,且真做也是技能层判定,不碰 #3 地基。

## 技术地基(现状 & #3 要建的东西)
- **出伤**:`Skill.computeDamage`(`mods/base-rules/handlers/skill/00_skill_lib.js`),`base属性 + add + Σ⌈属性×系数⌉`,各技能 YAML `damage:` 块声明。
- **减伤**:目前**只有普攻**走 `damage_calc.js`(`max(1, attack−defense)` + 防御×0.5);`basic_attack.yaml` 靠 `via_damage_calc:true` 进去。
- **关键现状**:**技能完全不过减伤**(`computeDamage` 出 raw → `applyDamage` 直接扣血),`defense` 对技能无效 → 没有"减伤公式的家"。
- **#3 的地基** = 建一个**唯一减伤收口**(提案 `Skill.mitigate(ctx, target, raw, type, element)`),普攻 / 技能 / DoT tick 全过它;`damage_calc.js` 改调它。这是公式的唯一定义处。
- ⚠️ 副作用:技能从此吃减伤 → 量级下降 + damage golden 需有意重生成 + 一轮重平衡。落地用"占位归一化先保战斗不崩,再配抗性做手感"(沿用 F2 策略)。

## #3 范围(已钉死)
- **#3 现在做 = 减伤地基**:投放标记(普攻/技能)+ 护甲曲线 + 三抗% + 元素轴(稀有)。现在就有用(修掉"技能无视防御"),且**预埋普攻/技能标记**,站位系统以后直接插上不返工。
- **站位系统**(lane 前线 + 短中长射程 + 站位 buff + 穿透 + 宠物/多单位)= **后续独立 feature**,跟宠物那摊一起做。详见 `docs/future-positional-pets-combat-running-notes.md`。

## 落地决策(已确认)
1. **上线 = 空跑框架**:护甲/抗性先全 0、数值≈不变,#3 只把减伤管线建好(修掉"技能无视防御")。配抗性/做手感另起一轮。
2. **元素只建框架**:零元素实体(火球暂不带元素),元素机制留到有 rider 设计时再配。框架支持随时纯数据加元素。
3. **防御落地**:现有 `defense`(皮甲/锁甲)→ 转成**护甲(只挡普攻)**;三抗 = **新词缀**;玩家早期默认无抗 → 故 **早期敌人以普攻为主**(被护甲挡),技能随玩家拿到抗装再变多。这是敌人/encounter 设计基调。
4. **敌我同轴**:怪也走"护甲挡普攻 + 三抗挡技能",encounter YAML 能配怪的护甲/三抗。
5. **普攻 = 永远走护甲、不带伤害类型**:没有"法术普攻绕过护甲"的例外;要绕甲就做成技能。普攻是独立的护甲通道,三种伤害类型只活在技能上。
