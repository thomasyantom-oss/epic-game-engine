# 未来:站位 / 宠物战斗 — Running Notes(脑暴 WIP,不是 spec)

> 后续 feature 的备忘,**不在当前 #3 范围**。等做宠物/多单位那摊时再正式设计实现。
> 由 Feature #3 伤害类型脑暴里溢出的站位构想沉淀而来。维护:Claude (Senior SDE)。2026-06-01。

## 为什么单独成篇
站位博弈的爽点要有**多个我方单位(宠物/队伍)排前后排**才兑现。现在只有光杆玩家一个单位,提前做站位=空转、也难测。所以 #3 只埋"普攻/技能"减伤标记当地基,这套站位系统跟**宠物/多单位**一起做。

## 核心构想(用户脑暴,待正式设计)
- **普攻只被护甲减免;技能被三抗(物/法/精)减免。** 这条已在 #3 地基里(`feature3-damage-types-running-notes.md`)。站位系统是它的玩法兑现。
- **普攻射程 = 打"纵列(lane)的最前排",不是整队最前排。** 顺着一条 lane 打进去,命中该 lane 最靠前的单位。→ 每条 lane 各自有前线:同 lane 前面站坦克就护住后面的人,隔壁 lane 前排是脆皮就自己暴露。(几何细节:3×3 grid,lane=纵列;待实现时确认行列定义。)
- **每单位有攻击距离 短/中/长**:短=只够前排;中=前+中排;长=全场。叠在 lane-前线规则上(近战只咬前排 lane,远程够后排)。
- **站位 buff**:站某排给增益(如前排减伤/后排增伤),让"站哪"本身是决策。
- **穿透技能**:贯穿射线那类无视前排直击后排,作为破站位的手段。
- **坦克型宠物**:高护甲单位站前排吃普攻当肉墙;破前排 → 后排暴露在普攻下。宠物是要做的、且重要。

## 立体站位 = 这几层叠加
lane 各自前线 × 单位射程(短中长)× 站位 buff × 穿透破局 × 护甲/三抗的定位分工 → 站位有纵深、有取舍、有破局。

## 与现有系统的接缝(实现时注意)
- 全建在现有 `CombatPosition`(row FRONT/MID/BACK + slot)+ 技能 targeting(pattern / targetRow/Col,见 SkillLib)上。
- #3 已埋"普攻/技能"投放标记 → 站位系统插上即可,不返工。
- 普攻 AI 目标规则需从"直接打玩家"改成"打 lane 最前占位单位";多单位到位后才有意义。

## 控制 / 豁免 / 韧性(更后续,挂 buff.apply,**不进 #3**)
减伤地基(#3)正交,这些是**控制/负面的施加层**机制,以后随"控制/Boss 机制"feature 做:
- **挂载点已现成**:`BuffService.applyBuff` fire 可取消的 `buff.apply` 事件 → 加这些 = 纯 mod handler,引擎/#3 零返工。
- **豁免**:`buff.apply` handler 对负面/控制 buff 掷概率,中了 `cancel`(玩家侧 RNG 抗性)。
- **韧性条(激战2 蔑视/Defiance)**:怪加 `韧性` 组件 + `buff.apply` handler;控制类 buff 先扣韧性(扣"控制量"),**没破不上控,破了才真上**(Boss 侧 CC 闸门)。
- 前向兼容:buff 已带 `positive: true/false`;需细分"控制类"时再加 `control` 标记,纯数据随时加。两者互补,不急。
