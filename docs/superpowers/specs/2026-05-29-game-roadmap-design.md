# 游戏开发路线图 — 设计文档

**日期:** 2026-05-29
**性质:** 路线图 / 子项目分解(元 spec)。每一章是独立的 brainstorm → spec → plan → 实现周期,本文件是它们的母文档。

---

## 1. 背景与方向

到目前为止做的都是引擎基建(微内核 / 战斗 / 动画 / 装备),还没有任何"游戏"——没有目标、没有成长循环、没有内容。本路线图规划从引擎走向游戏的开发顺序。

### 品类:单机回合制"刷子养成"游戏(给作者自己玩)

**核心论据:** 给自己玩的游戏,乐趣**不能**来自作者亲手编排的内容(剧情 / 关卡 / build 树),因为作者全知道。乐趣只能来自**连作者都预测不了结果的系统** = RNG + 大空间长周期数值优化 + 资源积累。

据此排除的方向:
- **轻肉鸽** — 场外成长揭示场内玩法,作者已知则失趣;自己搓 build 只会搓已知最强解。
- **传统 RPG** — 全是自编剧情 + 关卡设计,作者无可玩。
- **纯暗黑** — 攻防立体成长依赖格挡率 / 攻速 / 施法速度,在有限回合里失效或权重畸形(见 §4)。

### 取暗黑内核、弃暗黑战斗机制

目标 = **暗黑的"随机词缀刷子内核" + 回合制养成外壳**。

"MMO 刷副本"与"类梦幻打造"只是"随机产出来源"的皮(副本掉 vs 资源造),区别不大,**延后决定**(见 §6 Chapter 5)。

### 核心循环(已锁定)

```
活动 → 资源 → 随机产出(装备 / 技能料) → 角色变强 → 解锁更难的活动 → ……
```

## 2. 开发策略:做 mod,不做抽象框架

- 真正"品类中立"的基建(EventBus / ECS / ScriptRuntime / ModuleLoader / 热重载 / 快照渲染 / mod 系统)**已基本完成**——这才是"起重机"。
- 剩下的 stat 模型 / 资源循环 / 成长 / 叙事都是**品类形状的"建筑本身"**,无法中立抽象。强行抽象 = 空洞无用,或偷偷塞进品类假设。
- 因此:**把游戏 #1 具体地做成 mod(JS handler + YAML),不做抽象框架。** 通用抽象等游戏 #2 出现时再自然提炼(三次法则——零个实例提炼不出好抽象)。
- **"换品类 = 换 mod"**,引擎一颗螺丝不动,成本低,不是不可逆决策。

---

## 3. 三根支柱(玩家自述的"游戏感")

1. **剧情** — 带一些叙事 / 事件(最轻,放最后)。
2. **战斗挑战** — 战斗中有有意义的难度。
3. **资源积累 → 变强** — 基本盘。

---

## 4. 特色系统:技能为主角 + 灵魂标签升级(原则层)

> 本节只锁定**原则**。标签邻接表、属性 roll 范围、怪物→标签映射等具体机制,留给 Chapter 1 自己那轮深挖。

### 4.1 技能当主角 — 回合制立体成长的结构性正解

暗黑的成长维度是**实时战斗维度**(格挡率 / 攻速 / 施法速度),回合制天然敌视它们:回合数有限,一次格挡可能畸形地左右战局,攻速则失去意义。而**技能维度恰好相反——回合制对技能 synergy / 连携 / 排序是最友好的载体**,因为每回合都在"选一个技能",深度来自组合 / 时序 / 协同,不靠手速。

定调:**装备提供属性(燃料),技能决定属性怎么炸出来(发动机)。技能是主角。**

### 4.2 装备改写技能(已在架构里:modifier 定义在装备上)

装备不做纯属性棒子(只会变成"数字更大",无聊)。**最顶级的装备属性是"改写技能行为"**(+1 火球等级 / 火球额外弹射 / 灼烧可暴击 / 改写核心机制)。装备既保持兴奋感,又始终服务于技能主角。

### 4.3 灵魂标签升级树 — 把 RNG 从"结果"转移到"获取"

- 基础技能有**固定方向的升级版**,结果**作者亲手设计、已知、可平衡**:
  - 火球 + `爆破`标签 → **炎爆**(加命中 AOE)
  - 火球 + `多重`标签 → **连珠火球**
- 升级需要**灵魂技能标签**作材料。标签来自**会该技能的怪物**:
  - 骷髅法师(会灵魂爆破)→ 掉 `爆破` 灵魂球
  - 骷髅弓手(会多重箭)→ 掉 `多重` 灵魂球
- 获取走 RNG / 刷子:只有**刷出特殊词缀的灵魂怪**才掉灵魂球;或付出资源买"收灵魂的石头"去采集。

**关键:不可预知性在"你能不能 / 何时凑齐标签",不在技能长什么样。** 你知道想要炎爆,不知道何时拿到爆破球。"钓"的对象是灵魂球,不是技能本身 → 彻底规避"编辑器游戏"(Noita / 魔法工艺)的危险:没有任何技能是玩家自由拼出来的,全是追逐已知目标。

### 4.4 骨架 + 血肉 — 两层标签

- **结构 / 类型标签**(火焰、投射物、爆破、多重投射):决定技能*是什么*,靠**升级树**组合,结果确定 → 负责**自洽与骨架**,作者可平衡可读。
- **随机属性标签**(+伤害 / 暴击 / 穿透 / 附加灼烧):靠 **RNG** roll 到技能实例上 → 负责**复玩性**。炎爆是已知技能,但*你这一把的炎爆*独一无二。

同一套"骨架 + 血肉"对装备通用(装备 = 武器骨架 + roll 词缀)。统一生成底层仍然成立。

### 4.5 怪物 = 技能经济的供给侧

怪物不再只是障碍,它们是技能经济的供给侧。图鉴成为科技树——为升某技能去专门刷某怪。**特殊词缀灵魂怪 = 把"金光掉落"的兴奋感搬到敌人身上。** 这把技能系统(Ch1)与怪物生成(Ch3)焊成一条线。

### 4.6 约束(设计红线)

- **数值层不受扰动** — 升级 / 标签系统活在机制层,不破坏数值平衡。
- **依赖图无环** — 怪物 → 标签 → 技能的 gating 不能循环锁死(升 A 需怪 B 灵魂,而打怪 B 又必须先有 A)。
- **避免退化组合** — 随机属性层需约束 roll 空间,防止某 combo 无脑碾压、塌掉优化空间。

### 4.7 自觉的取舍(记录在案)

本模型用**涌现换控制**:作者知道所有技能(炎爆 / 连珠火球皆作者所写),离最初"连我都不知道出什么"的激进愿景远了一截,更接近"ARPG 技能树 + 材料 gating"。这是被验证过的安全做法——复玩性来自 RNG 获取 + build 组合 + 难度,不来自"技能是谜"(暗黑的技能全在 wiki 上,照样耐刷)。血肉层(§4.4)把一部分"实例独特性"找补回来。

## 5. Chapter 路线图

排序逻辑:**先做"决定好不好玩、且无法延后 / 无法中立设计"的,后做"贴皮"的。**

### Chapter 1 — 技能成长内核(旗舰)
build 空间的主轴。技能如何把属性炸成战斗效果;灵魂标签升级树(骨架);随机属性标签(血肉);RNG 在获取不在结果。**心脏,无法中立设计,必须第一。** 深挖时第一个要拍的旋钮:组合标签能否再参与升级(深度 vs 爆炸)。

### Chapter 2 — 随机词缀装备系统(随机产出引擎)
装备从 Ch1 的属性轴上 roll 随机词缀 + 稀有度分层 + loot 生成器,含"改写技能"的高级词缀。反过来验证 Ch1 的轴能否 roll 出有意思的 build。

> **里程碑 A:** 做完 1 + 2,已有可玩最小闭环「打 → 掉随机装 / 灵魂料 → 优化 build」。**停下来自己玩,检验手感。**

### Chapter 3 — 挑战与敌人生成
带随机词缀的怪物 + 难度分层。给"优化 build"一个目的;同时怪物是灵魂标签的供给侧(与 Ch1 焊接)。闭合战斗侧循环。

### Chapter 4 — 资源与养成循环
货币 / 材料 + sink:打造 / 升级 / 洗练 / 收灵魂石,把资源转成战力。显式做出 `活动 → 资源 → 变强` 主干。装备"改写技能"高级词缀的具体抠法落在这里。

### Chapter 5 — 活动结构与内容皮
到此才拍 **MMO 刷副本 vs 梦幻打造**(或两者都要)。搭副本 / 日常 / 解锁推进 / 世界结构。之前延后的皮肤决策落地。

### Chapter 6 — 叙事 / 事件层(剧情)
最轻支柱,放最后。作者亲手编排的内容(对自己复玩性最低),且依赖前面系统都在才好往上织事件。
