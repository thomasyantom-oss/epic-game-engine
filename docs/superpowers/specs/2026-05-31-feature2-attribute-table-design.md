## 0. 定位

把一维的 `attack` 标量,换成 **5 基础属性 → 5 二级属性** 的两层属性表,作为 Ch1 build 空间的主轴。技能通过 `scaling` 吃属性,Ch2 装备、Ch3/#7 升级树都将挂在这张表上。

本 feature **只造第一层(通用派生)**:基础属性 → 二级属性的线性换算 + 技能 scaling 接入 `computeDamage`。主属性的"第二层专属加成"由专精(#6)解锁,本轮只留数据位。

---

## 1. 设计原则(实现时不得违反)

1. **安全属性 vs 高级属性分治(主心骨)。** 基础属性只产**线性、可白嫖的"基础量"**——物理强度 / 法术强度 / 精神强度 / 最大生命 / 先攻。所有**非线性、会滚雪球**的强力属性——暴击、暴伤、命中、穿甲、格挡、闪避、减伤——**禁止随等级或基础属性白给**,只能来自装备 / buff / 专精。这条挡掉"某职业后期靠堆属性把高级属性叠爆"的失衡。

2. **强度 = 纯资源。** 三种强度只是数值池,**具体加成效果完全由技能 `scaling` 自己声明**,属性侧不定义任何效果语义。

3. **主属性第二层 = 专精(#6)解锁。** 未专精 = 全员只有第一层通用派生;选专精才长出主属性专属的第二层。#2 不实现第二层,只保证数据结构能让 #6 挂上去。

4. **全局向上取整。** 所有派生计算、伤害结算的取整一律 `Math.ceil`。

5. **§1.9 refinement —— 技能 scaling 吃"强度",不吃裸基础属性。** 母文档 §1.9 草图写的是 `scaling:{智力:1.2}`(吃裸属性);本 feature 改为吃**三强度 / 最终武器伤害**(强度由属性派生)。意图一致(技能吃属性),但接口更干净:Ch2 装备可直接 `+法强`、buff 可直接改强度,无需穿透到基础属性。**这是对母文档的有意演进,非漂移。**

## 2. 属性模型(规范表)

### 2.1 基础属性 → 二级属性

| 基础属性 | 武器伤害倍率 | 额外二级属性 |
|---|---|---|
| **力量** | **×2**(全表唯一特殊倍率) | —(纯武器输出,无 utility) |
| **敏捷** | ×1 | 先攻 |
| **智力** | ×1 | 法术强度 |
| **体质** | ×1 | 最大生命 |
| **意志** | ×1 | 精神强度(抗控免疫 + 部分技能加值) |

- **力量 = 专职输出**:唯一职责是武器伤害,但 2 倍速率。其余四条 = 1 倍武器伤害 + 一项 utility → 纯力量=玻璃炮,余者=输出换功能。力量过减伤、占装备格吃亏,2 倍是补偿。
- **武器决定吃哪条属性(A2)**:力量斧吃力量×2、匕首吃敏捷×1、法杖吃智力×1……武器系统是 **Ch2**;#2 无武器,用职业默认属性驱动物理强度。

### 2.2 五条基础二级属性

| 二级属性 | 来源 | 性质 |
|---|---|---|
| **物理强度** | 当前武器对应属性 × 倍率 | 武器伤害**百分比倍率**;非武器物理技能(战吼类)直接吃它 |
| **法术强度** | 智力 × 系数 | 绝对值;法术伤害/治疗技能吃它(法师施法源) |
| **精神强度** | 意志 × 系数 | 绝对值;部分技能加值 + 抗控(德鲁伊施法源)。效果延后,#2 只派生数值 |
| **最大生命** | 体质派生 | 存于 Health.maxHp |
| **最大魔力 / 资源** | **不由基础属性派生** | 专精换条(盗贼能量 / 狂战怒气),归 #6;#2 保留默认法力条 |

> **法师吃法强、德鲁伊吃精神**——各自主属性 = 各自施法源,两条强度并存不串味。

### 2.3 派生系数(定稿)

```
物理强度(%) = 武器属性 × 倍率          力×2 / 余×1   (#2 无武器 → 职业默认属性)
法术强度    = 智力 × 1
精神强度    = 意志 × 1
最大生命    = 50(base) + 体质 × 10
先攻        = 敏捷(+ 基础)
最终武器伤害 = ⌈武器基础 ×(1 + 物理强度%)⌉   普攻 = 此值;真公式待 Ch2
```

- **物理强度是百分比加成值**(力量 14 → +28%)。`最终武器伤害 = ⌈武器基础 ×(1 + 物理强度/100)⌉`。纯乘已废(太离谱)。
- **最终武器伤害的精确公式留待 Ch2 武器到位再定**;#2 用占位武器基础先跑通管道。

## 3. 数据模型与 ModifierChain

### 3.1 新组件 / 字段
两类属性,术语固定:
- **基础属性(primary)** = 玩家加点拥有的 5 条:力量/敏捷/智力/体质/意志。
- **二级属性(derived)** = 从基础属性算出来的产物:物理强度/法术强度/精神强度/最大生命/先攻。玩家不直接加。

存储:
- 新组件 **`PrimaryStats { 力量, 敏捷, 智力, 体质, 意志 }`**——基础属性,加入角色 schema 的 `base_components`。
- 新组件 **`DerivedStats { 物理强度, 法术强度, 精神强度 }`**——三强度的存储盒子(与 `CombatStats` 分开,基础/派生清晰隔离,快照可单独开"二级属性"块)。`maxHp`→Health,`先攻`→CombatStats.speed。纯代码归类,不影响玩法数值。

### 3.2 派生 modifier(衍生自衍生)
- `modifier_types.yaml` 新增 type **`derived`**,**priority 排在所有属性来源之后**(class/level/equipment/buff 都先跑,派生最后跑),保证读到累加后的基础属性值。
  - 注:`ModifierChain` 按 priority **升序应用**(数字小的先跑)。现状 race200…buff10。派生要最后跑,故 `derived` 取**高于 200** 的 priority(具体值 plan 定)。
- 派生 modifier 的 `apply(entity)`:读 `PrimaryStats` → 写三强度 + maxHp + speed,全程 `Math.ceil`。
- 运行时值(hp/mp)保护沿用现有 `before/after_recalculate` 钩子(`recalculate_hooks.js`)。

## 4. 职业(5 个,覆盖全部 5 条基础属性)

| 职业 | 主属性 | L1 力/敏/智/体/意 | 每级 +5 | scaling 源 |
|---|---|---|---|---|
| **战士** | 力量 | 14 / 5 / 3 / 10 / 3 | 3力 2体 | 物理强度 · 最终武器伤害 |
| **法师** | 智力 | 3 / 5 / 14 / 5 / 6 | 3智 1敏 1体 | 法术强度 |
| **盗贼** | 敏捷 | 5 / 14 / 3 / 6 / 3 | 3敏 1力 1体 | 物理强度 · 最终武器伤害 |
| **德鲁伊** | 意志 | 3 / 5 / 3 / 8 / 13 | 3意 1体 1敏 | 精神强度 |
| **护卫** | 体质 | 5 / 3 / 3 / 15 / 6 | 3体 1力 1意 | 物理强度 / maxHp |

- 这 5 个各主一条基础属性 → **测试矩阵天然全覆盖**。
- 职业 schema 改造:从现有"直接 `+attack/+maxHp` 写死的二级数值",改为**声明起始 `PrimaryStats` + 主属性 + 默认武器属性**;二级数值改由派生 modifier 算出(A:纯净迁移)。

## 6. 技能 scaling 接入 computeDamage(Feature #1 接缝)

`00_skill_lib.js::computeDamage` 在 `// Feature #2 将在此处追加属性加成` 处扩展:

```js
var base  = dmgSpec.base ? CombatStats[dmgSpec.base] : 0;
var total = base + (dmgSpec.add || 0);
if (dmgSpec.scaling) {                      // 新增:吃三强度
  var ds = caster 的强度来源组件;
  for (attr in dmgSpec.scaling)
    total += Math.ceil(ds.getInt(attr) * dmgSpec.scaling[attr]);
}
return total;
```

- **`computeDamage` 仍是伤害唯一真相源**——scaling、面板预览、AI 全走它。
- **火球迁移**:`base:attack, add:10` → **`add:8, scaling:{法术强度:0.5}`**(法师 L1 法强 14 → 8+⌈14×0.5⌉=15,贴近现值 20 的量级)。其余法术技能(ice_beam 等)同步迁到法强。
- **战吼类(非武器物理)** → `scaling:{物理强度:k}`。
- **普攻 / 近战攻击** → 吃最终武器伤害(=武器基础×物理强度);#2 用占位武器基础,`damage_calc.js` 同步迁移到物理强度体系。

### 6.1 敌人统一走属性派生(玩家/敌人同轴)
**敌人也由这 5 条基础属性构成**,不单列裸 stat —— 战力与玩家在同一根轴上可比,`computeDamage` 对敌我完全一致(敌人 `物理强度` 同样驱动它的攻击)。

- encounter YAML 从写死 `attack/hp/speed` → **写死敌人的 `PrimaryStats`(力/敏/智/体/意)**;hp/物理强度/先攻经**同一个派生 modifier**算出。
- 敌人 spawn 路径也注册派生 modifier + `setBase` + recalculate(实现细节 plan 定)。
- `training_dummy`(attack 0)= 全 0 攻击属性,照样兼容。

### 6.2 ⚠️ 数值量级 + 重平衡(本轮落地最需小心)
普攻从 `attack-defense` 迁到物理强度体系后,**数值量级会变**(方案 A 本含重平衡)。"重平衡"在此=**给每个敌人设计 `PrimaryStats`**,让派生出的二级落在目标难度,而非重调裸 attack。落地策略:**先用占位归一化把物理伤害落回当前量级保证战斗不崩**,Ch2 武器到位再调真值。实现阶段单列一节处理玩家普攻 + 全部 encounter 的属性迁移。

## 9. 测试网

- **派生正确性**:给定 `PrimaryStats`,三强度 + maxHp + 先攻按系数算对(含 `Math.ceil`)。
- **衍生自衍生顺序**:class/level/equipment 改了基础属性后,派生 modifier 读到的是**累加后**的值(priority 排序验证)。
- **computeDamage scaling**:三强度各驱动一条技能,伤害含 scaling 项且向上取整。
- **5 职业起始值**:每个职业 L1 的基础属性 + 派生预览符合 §2.3 / §4。
- **敌人属性派生**:encounter 的 `PrimaryStats` 经同一派生 modifier 算出 hp/物理强度/先攻;spawn 路径注册派生 + recalculate 正确。
- **每级成长**:升级后按职业模板 +5 属性点,二级属性自动重算。
- **火球迁移不破坏**:fireball golden 重生成后逐字节锁(Feature #1 的 `SkillFidelityTest` 网保护);其余战斗回归(`CombatBugfixTest` / 现有集成测试)绿。
