# 文字 RPG 引擎设计文档

## 概述

单人文字 RPG 游戏引擎，经典奇幻设定，网页端运行，点击链接交互。引擎与内容完全分离，所有游戏内容通过 Mod 系统加载。

## 核心设计哲学

- **涌现复杂度**：少量维度互相作用产生超越各自之和的深度（11×11 > 10×10 = 100 > 1×100）
- **数据驱动**：一切系统可扩展，通过配置/数据而非硬编码
- **汉字 + 颜色**：利用汉字的信息密度和颜色的语义表达作为核心视觉语言
- **引擎与内容分离**：框架本身不包含游戏内容，原版内容也是一个 Mod

## 技术栈

| 层         | 技术                  | 职责                         |
| ---------- | --------------------- | ---------------------------- |
| 后端       | Java (Spring Boot)    | 所有游戏逻辑、API 服务       |
| 前端       | Vue                   | 纯展示层 + 玩家输入收集      |
| 数据库     | H2/SQLite             | 数值/关系型数据              |
| 配置文件   | YAML/Markdown         | 叙事内容、描述文本           |
| 资源       | 文件系统              | 图片、音频等资源文件         |
| 通信       | REST API              | 前后端通信，预留 WebSocket   |

## 运行方式

- 单机：本地起 server，浏览器访问 localhost
- 多人（未来）：同一 server 部署到远程，前端连接远程地址

## 系统架构

### 前后端职责划分

**后端：**
- 处理所有游戏逻辑（战斗、移动、物品、对话等）
- 返回结构化 JSON（带颜色标记的文字、可点击选项、状态数据）
- 管理存档
- 加载和管理 Mod

**前端：**
- 接收 JSON，渲染带颜色的汉字和可点击链接
- 多面板 UI 系统
- 玩家 UI 自定义（CSS 变量驱动）
- 不做任何游戏逻辑判断

### 前后端通信

- 玩家操作 → 前端发 API 请求
- 后端返回：操作结果 + 需要刷新的面板列表
- 前端根据列表按需刷新对应面板
- 后续可升级 WebSocket 实现服务端主动推送

### 多面板 UI

- 每个面板是独立 Vue 组件（主场景、背包、地图、状态栏、对话等）
- 面板的显示/隐藏由玩家操作或游戏事件控制
- 新增面板 = 新增 API + 新增 Vue 组件，不改已有代码

### 玩家 UI 自定义

- 前端维护用户偏好配置（存 localStorage）
- 可自定义项：字体大小、背景颜色、面板边框样式/颜色、文字颜色主题等
- CSS 变量实现，改一个变量全局生效
- 设置面板可随时扩展新自定义项

## 核心游戏系统

以下系统均以最大可扩展性设计，具体规则通过 Mod 数据定义。

### 职业系统

- 多职业叠加（类似 ToME4）
- 每个职业有若干专精树
- 专精之间可产生联动效果
- 支持转职：满足条件后解锁新职业，旧职业专精保留
- 职业、专精、联动规则各自独立定义，通过配置组合

### 装备系统

- 装备有基础属性 + 词缀/特殊效果
- 装备效果可与职业专精互动
- 装备槽位可配置扩展

### 克制系统（预留）

- 标签机制：实体（怪物、技能、装备）可携带标签
- 克制规则通过标签间关系定义（tag → tag + 倍率）
- 架构预留，具体规则后续填充

### 战斗系统

- 回合制，每回合展示状态 + 可用行动选项
- 伤害/效果计算考虑：属性、装备、职业专精、克制关系
- 支持快速战斗（自动选择，加速演算，展示结果）

### 世界结构

- 开放世界基调，由区域和场景组成
- 地图可能支持随机生成（参考 For the King）
- 模块化接入：副本、突发事件、任务系统等
- 具体世界内容待定，架构保证灵活性

## Mod/DLC 系统

### 架构

```
游戏引擎（框架）
  ├── 基础 Mod（原版内容）
  ├── DLC Mod（官方扩展包）
  └── 第三方 Mod（社区内容）
```

### Mod 能力分层

1. **内容层** — 添加新怪物、装备、地图、职业等，纯数据/配置
2. **规则层** — 修改伤害公式、克制关系、战斗流程，通过覆盖或扩展规则配置
3. **机制层** — 添加全新系统（坐骑、炼金等），通过插件接口注入引擎

### Mod 结构

- 每个 Mod 是独立文件夹
- 包含自己的配置、数据、资源文件
- 声明元信息（名称、版本、依赖、冲突）

### Mod 加载

- 引擎启动时按加载顺序读取所有 Mod
- 后加载的 Mod 可覆盖先加载的内容/规则
- 关键系统暴露扩展点（钩子/接口），Mod 可注册自己的逻辑
- Mod 间可声明依赖和冲突关系

## 数据分层

| 数据类型         | 存储方式          | 示例                     |
| ---------------- | ----------------- | ------------------------ |
| 数值/关系数据    | 数据库            | 属性值、掉落率、克制倍率 |
| 叙事/描述        | YAML/Markdown     | 场景描述、对话文本       |
| 资源文件         | 文件系统          | 图片、音频               |
| 玩家存档         | 数据库            | 角色状态、进度           |
| 玩家 UI 偏好     | localStorage      | 字体、颜色、布局设置     |

以上数据均由 Mod 提供，引擎本身不含游戏内容。
